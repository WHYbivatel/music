# Готовность backend music.esl.kz

Аудит по коду и процессам на 16 октября 2026. Предыдущие описания контракта в README не считались доказательством реализации.

## Что есть

- Корень: `/var/www/music.esl.kz`. Git: `origin` `https://github.com/WHYbivatel/music.git`, HEAD detached на `fbecbaa`, в рабочем дереве незакоммиченные изменения интерфейса.
- Публикация: PM2-процесс `music.esl.kz`, `next start -H 127.0.0.1 -p 3220`. Nginx `music.esl.kz` проксирует только на этот порт. Порт 3100 занят другим приложением и не используется этим сайтом.
- Стек интерфейса: Next.js 16, React 19, TypeScript. Сборка `npm run build`, проверка `npm test` и `npm run typecheck`.
- Данные студии, баланс, заявки, черновик и демоадминка живут в `localStorage` / `sessionStorage` (`lib/store.ts`, `lib/engine.ts`, `lib/adapters.ts`). `NEXT_PUBLIC_DATA_MODE=mock`.
- `apiAdapter` описан, сервера за ним не было. Пароль не принимался. Демоадмин `admin@demo.auen.local` / `neon-admin-demo` — только mock.
- Общие PostgreSQL и Redis на `127.0.0.1` уже работают. Своей базы, роли, очереди и каталога аудио у music.esl.kz не было.
- PWA не кэширует `/v1/`, `/api/`, админку, вход, профиль и пополнение.

## Чего не было

Аккаунты, сессии, PostgreSQL-схема, серверный журнал токенов, очередь, worker, хранилище аудио, почтовый адаптер, серверная админка.

## Решение

Не дублировать второй интерфейс. Оставить Next.js и подключить свой FastAPI на `127.0.0.1:3221` через rewrite `/v1` (один origin, порт наружу не публикуется).

- PostgreSQL: база `music_esl`, роль `music_esl`.
- Очередь: Redis с префиксом `music.esl.kz:` и свой worker. Библиотека доставки — `redis`. Отдельный брокер не добавляется.
- Миграции: Alembic, одна цепочка в `server/alembic`.
- Аудио: локальный каталог `/var/lib/music.esl.kz/media` вне сборки, пока S3 не задан. Это не общий диск сайта и не замена bucket.
- Провайдер музыки: `MockMusicProvider`. ACE-Step только в конфигурации, без весов и без тихого отката на mock.

## Этапы

1. Аудит и этот документ — сделано.
2. База `music_esl`, Alembic, Argon2id, сессии и CSRF — сделано в `server/`.
3. Черновики и библиотека с проверкой владельца — сделано.
4. Журнал токенов, резерв, списание и возврат в транзакции — сделано.
5. Outbox, Redis-доставка, worker, `MockMusicProvider` — сделано. ACE-Step только конфигом.
6. Локальное хранилище `/var/lib/music.esl.kz/media`, Range и короткая ссылка на скачивание — сделано. S3 не создавался.
7. Заявки и админка с основанием решения — сделано. Реальные переводы выключены. Почта не настроена.
8. Проверки и выпуск — опубликовано. Интерфейс в режиме `api`. Инструкция запуска и восстановления: `docs/operations.md`.

## Проверено 16 октября 2026

- Pytest backend на PostgreSQL `music_esl_test`: 9 сценариев, включая изоляцию владельца, идемпотентность, параллельный резерв, одно списание, один возврат, повторное подтверждение заявки, потерю Redis и ошибку хранилища.
- `npm test` и `tsc --noEmit` проходили до выпуска. Сборка Next.js опубликована процессом `music.esl.kz`.
- Публичный путь `https://music.esl.kz/v1`: готовность, гостевой демобаланс, регистрация, задача тестового провайдера до `succeeded`, Range `206`, тестовый баланс, админский обзор `403`, восстановление пароля `503 error.mail`.
- Браузер: гостевая генерация, смена языка с сохранением описания и тега, библиотека, плеер с перемоткой и сохранённой позицией при переходе в библиотеку, вход, отказ обычному пользователю в админке, выход с очисткой данных аккаунта. На ширине 1440 мобильная навигация и предложение установки не видны.
- `pm2 save` выполнен. Процессы: `music.esl.kz`, `music.esl.kz-api`, `music.esl.kz-worker`, `music.esl.kz-dispatcher`.

Секреты только в `/var/www/music.esl.kz/.env` (не в git). Общий Nginx, чужие базы и чужие процессы не меняются.

Локальные файлы аудио пропадут вместе с диском этой машины. Для нескольких экземпляров нужен приватный S3 и отдельные ключи.
