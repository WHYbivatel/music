# NEON SOUND

Локальный интерактивный frontend музыкальной студии: Next.js 16, React 19, TypeScript, Tailwind CSS 4, Motion for React. Модель, реальные платежи и публичная публикация не подключены.

## Запуск

Нужен Node.js 20.9+ (проверено на Node.js 26).

```sh
npm install
npm run dev
```

Открыть http://127.0.0.1:3100. Порт выбран, чтобы не занимать уже используемый 3000.

```sh
npm test             # тесты расчётов, переходов, идемпотентности и контраста
npm run typecheck    # TypeScript
npm run build        # production-сборка
npm start            # production на 127.0.0.1:3100
```

## Страницы

- `/` — студия: описание, примеры, жанры, назначение, вокал/инструментал, длительность, дополнительные настройки, процесс и результат.
- `/library` — поиск по названию, фильтры, сортировка, сетка/список, избранное, переименование, скачивание WAV, удаление с подтверждением.
- `/balance` — пакеты, заявка, маска реквизитов, копирование номера заявки, ожидание проверки, история и переход в отдельную админку.
- `/profile` — демопрофиль, имя, баланс, операции, движение, выход и сброс демонстрации.
- `/login`, `/register` — честные экраны входа в деморежим без ввода/сохранения пароля.
- `/ui-kit` — интерактивные компоненты и состояния, цвета, скругления, интенсивность и режим движения.

## Рабочие демосценарии

1. На старте — **50 демотокенов** и три аудиопримера. Это локальный демонстрационный баланс, не обещание бонуса пользователям будущего сервиса.
2. Достаточно одного описания. Стоимость: 5 токенов за каждые начатые 30 секунд; 30/60/120/180 секунд стоят 5/10/20/30 токенов.
3. «Создать трек» резервирует стоимость. Очередь сменяется созданием и результатом. Нет вымышленных процентов или времени ожидания. Результат — один вариант; повтор оплачивается отдельно.
4. В «Инструментах деморежима» под студией можно сымитировать ошибку. Резерв освобождается, появляется операция возврата; повтор доступен. Ошибка не создаёт трек.
5. Перезагрузка во время задания восстанавливает его по сохранённому времени. Завершение, возврат и подтверждение заявки идемпотентны. Web Locks сериализуют локальные финансовые переходы между вкладками, где браузер их поддерживает; без Web Locks используется очередь в пределах вкладки.
6. Плеер действительно воспроизводит локальный WAV нужной длительности, поддерживает перемотку, громкость и паузу. Визуализация декоративная, не анализирует аудиосигнал.
7. Пакеты: Старт 15 000 ₸ / 300 токенов; Создатель 35 000 ₸ / 800 токенов (по умолчанию, «Рекомендуем»); Студия 65 000 ₸ / 1 600 токенов. Количество двухминутных генераций рассчитывается из конфигурации: 15 / 40 / 80. Цены — предварительная продуктовая гипотеза.
8. Выбрать пакет → создать заявку → «Я оплатил» → «Ожидает проверки». **Баланс не меняется** до подтверждения в админке. Отклонение не зачисляет токены. Повторное подтверждение не зачисляет их повторно.
9. Реальные реквизиты отсутствуют: показана маска, копирование отключено. Копируется только номер заявки. Никакого реального перевода не требуется.
10. Данные, настройки треков, избранное и черновик сохраняются в localStorage. «Сбросить демоданные» в профиле возвращает исходные примеры и 50 демотокенов.

Это прототип: браузерное хранилище можно изменить вручную, очистить или потерять. Защита демонстрации от случайных повторов не является серверной финансовой гарантией.

## Общий UI kit

- `app/globals.css` — семантические CSS-токены, связанные с Tailwind через `@theme inline`. Шкалы текста, отступов, скруглений, поверхности, фокус, переходы, адаптивность.
- `components/ui.tsx` — Button, Badge, Panel, Select, Chips, Switch, Modal, Skeleton, Empty, уведомления и анимируемый баланс.
- `components/ui-kit.tsx` — демонстрационная страница. Изменения темы сохраняются отдельно, в `neon-theme`, и применяются ко всему приложению.
- `lib/config.ts` — имя продукта, цены, валюта, пакеты, единая функция стоимости, примеры и параметры Motion.
- Акцент по умолчанию `#F34BA5`, фон `#09090F`, поверхности `#14141E`/`#1D1D2B`, вторичный цвет `#9875FF`.
- Стандартная палитра проверяется тестом на контраст AA текста. Произвольный цвет из UI kit может ухудшить контраст; это инструмент проверки оформления, а не автоматический генератор доступных палитр.

## Анимации и производительность

Официальные исходники React Bits находятся в `components/react-bits`; лицензия сохранена в `LICENSE.md` рядом с компонентами. Происхождение и локальные изменения — в `THIRD_PARTY_NOTICES.md`.

Aurora — слабое свечение сверху; на время задания она демонтируется, единственным большим WebGL-эффектом становится Orb. Уменьшение движения, отключение анимаций, отсутствие WebGL2 и устройства с малым количеством ядер/памяти переключают декоративную графику на CSS-градиенты. Компоненты приостанавливают requestAnimationFrame по visibilitychange и IntersectionObserver. Magnet используется только для главного действия и точного указателя, смещение ограничено 3 px. Click Spark запускается **императивно после принятия задания**, не на pointerdown. Star Border не запускает clickPulse. Spotlight работает на карточках пакетов. Count Up показывает фактическое изменение баланса.

MotionConfig управляет общими переходами; Canvas/WebGL и CSS отдельно учитывают full/reduced/off и системный prefers-reduced-motion. Диалоги используют нативный `<dialog>` с focus trap, Escape и возвратом фокуса. На телефонах — нижние диалоги и навигация, плеер над навигацией.

## Подключение backend

Скопировать `.env.example` в `.env.local`:

```dotenv
NEXT_PUBLIC_DATA_MODE=api
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000
```

Перезапустить Next.js. `api` **не подставляет mock-данные**: без адреса или при ошибке появляется понятное состояние подключения с повтором. Mock и API используют отдельные локальные ключи. В API-режиме баланс и библиотека обновляются с сервера, статусы задач опрашиваются; локальное завершение задач и демопанель администратора выключены.

`lib/types.ts` — интерфейс AppAdapter, DTO Settings, Track, Job, Payment, Operation. `lib/adapters.ts` — mockAdapter и apiAdapter; `lib/engine.ts` — чистые переходы mock-режима; `lib/store.ts` — клиентская подписка и локальные транзакции. UI вызывает адаптеры для авторизации, задач, библиотеки, баланса и заявок.

### Предлагаемый контракт `/v1`

Все даты в DTO — Unix timestamp **в миллисекундах**. JSON отвечает camelCase. Ошибки — не-2xx; текущий клиент отображает безопасное сообщение со статусом, а не произвольный HTML сервера.

| Метод | Путь | Запрос → ответ |
|---|---|---|
| GET | `/auth/me` | → `{name,email}` или `null` |
| POST | `/auth/demo` | → `{name,email}` (заменить реальным входом при интеграции) |
| POST | `/auth/logout` | → 204 |
| POST | `/generations` | Settings + `Idempotency-Key` → Job |
| GET | `/generations/active` | → активный Job или `null` |
| GET | `/generations/:id` | → Job: queued / generating / ready / error |
| GET | `/tracks` | → Track[] |
| PATCH | `/tracks/:id` | `{title?,favorite?}` → 204 |
| DELETE | `/tracks/:id` | → 204 |
| GET | `/tracks/:id/download` | → `{url}` (временная ссылка S3) |
| GET | `/balance` | → `{available,reserved}` |
| GET | `/balance/operations` | → Operation[] |
| GET | `/payments` | → Payment[] |
| POST | `/payments` | `{packageId}` + `Idempotency-Key` → Payment |
| POST | `/payments/:id/paid` | → 204; переводит awaiting_payment в pending_review |

Track содержит `audioUrl` для воспроизведения, `settings`, `cover` (номер локального абстрактного оформления) и `favorite`. `download` получает отдельную ссылку через адаптер; для загрузки cross-origin S3 должен разрешать CORS. В текущем прототипе `demo:true` и синтезированный аудиопример явно обозначены; при реальной интеграции расширить DTO для серверных обложек и происхождения аудио.

Будущий FastAPI должен **самостоятельно** валидировать настройки, вычислять стоимость по серверной конфигурации, авторизовать пользователя и все изменения баланса. Резерв/списание/освобождение — атомарные транзакции PostgreSQL. Уникальные ключи идемпотентности должны проверяться на сервере. Очередь Redis передаёт задания GPU-сервису ACE-Step; результат и signed URLs — S3. Подтверждение/отклонение перевода доступно только серверному администратору; endpoint не включён в публичный frontend-адаптер. Для реальной авторизации нужны HttpOnly cookies, CSRF и корректный CORS. Секреты платежей, S3 и GPU **не помещать** в NEXT_PUBLIC_* или frontend.

## Аудио и обложки

`node lib/assets.mjs` воспроизводимо создаёт оригинальные SVG-обложки и простой трёхминутный инструментальный loop, а также WAV-версии по 30/60/120/180 секунд. Это собственные процедурные материалы проекта (CC0), внешние медиа не используются. Аудио **не генерируется по описанию**, не содержит вокал и одинаково по музыкальному содержанию для всех запросов; длительность соответствует выбранной. В интерфейсе это объясняется в результате и информации о треке.

## Проверки

Автотесты: формула округления и пакеты; резерв и однократное списание; восстановление задания; возврат при ошибке; пустой запрос и недостаток средств; подтверждение и отклонение платежа; название/длительность аудио; отсутствие молчаливой подмены API; контраст стандартной палитры.

Ручная проверка в браузере: широкий и мобильный экран, успешная и неуспешная генерация, воспроизведение реального WAV, начисление через демопанель, библиотека, UI kit, режим Off, закрытие диалога по Escape и сохранение после перезагрузки. Production-сборка и TypeScript выполняются отдельно.

## Админка

Открыть `/admin` или выбрать «Админка» в меню студии. Спокойная графитовая тема с серо-зелёным акцентом отделяет управление от творческой студии.

Демоданные уже указаны на экране входа:

- Логин: `admin@demo.neonsound.local`
- Пароль: `neon-admin-demo`
- Кнопка: **«Войти в демоадминку»**. Вводить ничего не нужно.

Это открытый тестовый доступ, а не настоящие учётные данные. В mock-режиме сессия хранится в sessionStorage этой вкладки. Прямое открытие административного URL без демосессии показывает вход. В API-режиме демовход отключён; права должны проверяться сервером.

Разделы:

- `/admin` — сводка покупок, пользователей, очереди проверок, активности за 7 дней и последних событий.
- `/admin/audit` — журнал с поиском по имени/email/описанию/объекту, фильтрами типа события, периода и источника; пагинация, детали и CSV-экспорт текущей выборки. CSV экранирует кавычки и формулы.
- `/admin/users` — локальный пользователь и четыре явно обозначенных примера; покупки в тенге, баланс, количество генераций, последнее посещение и история пользователя.
- `/admin/payments` — список заявок и их статусы, подтверждение/отклонение с отдельным диалогом.
- `/admin/generations` — задания этого браузера, резерв/списание/возврат и результат.

Примерные пользователи и заявки имеют метку **«Пример»**. Их подтверждение меняет только учебную заявку и аудит, без зачисления в кошелёк студии. Заявки с меткой **«Этот браузер»** связаны с реальным локальным демобалансом: подтверждение зачисляет токены ровно один раз. Журнал сохраняет исторические события, в том числе исходный статус примера до решения администратора.

`lib/audit.ts` описывает события и централизованно фиксирует принятые переходы платежей, генераций и треков. Отдельно пишутся вход/выход, посещения страниц, скачивания и вход администратора. События содержат участника, роль, время, объект, сумму/токены, результат и источник. Время в админке — **Asia/Almaty (UTC+5)**. Черновики не засоряют журнал. Локальный журнал ограничен 2000 событиями; сброс демонстрации заменяет его событием сброса. Это редактируемый браузерный прототип, а не защищённый серверный audit trail.

`lib/admin.ts` — интерфейс данных и адаптер админки. Предлагаемые дополнительные API:

| Метод | Путь | Ответ / поведение |
|---|---|---|
| GET | `/v1/admin/session` | Actor или null; серверная проверка административной сессии |
| POST | `/v1/admin/logout` | Завершить сессию |
| GET | `/v1/admin/overview` | AdminSnapshot: users, payments, audit, jobs |
| POST | `/v1/admin/payments/:id/confirm` | Идемпотентно подтвердить перевод, зачислить токены и записать аудит |
| POST | `/v1/admin/payments/:id/reject` | Идемпотентно отклонить заявку и записать аудит |

Перед реальной эксплуатацией авторизация, роли, аудит, фильтрация/пагинация и операции платежей должны работать на сервере; браузер не является источником истины. Демопароль не отправляется в API. Финансовые административные endpoints должны проверять роль, CSRF и ключ идемпотентности, а аудит — храниться в PostgreSQL отдельно от пользовательского редактируемого состояния.

## PWA и мобильная установка

Манифест `/manifest.webmanifest` включает standalone-режим, русское название, theme color, иконки PNG 192/512, maskable-иконку и ярлыки студии/библиотеки. Apple Touch Icon — 180×180. Исходный генератор оригинальных иконок: `node scripts/pwa-icons.mjs`.

Кнопка **«Установить приложение»** есть в студии и в меню админки. Если браузер предоставляет системное приглашение, кнопка вызывает его. В остальных случаях показывает инструкцию; на iPhone/iPad — Safari → «Поделиться» → «На экран Домой». Установка не запускается автоматически. Системный статус standalone учитывается.

Service worker включается **только в production**, чтобы не кэшировать меняющиеся dev-сборки:

```sh
npm run build
npm start
```

Для проверки предварительно остановить `npm run dev`, если он занимает порт 3100. Затем открыть приложение, дождаться регистрации worker и проверить повторное открытие. Worker заранее сохраняет публичную оболочку студии, её JS/CSS, обложки и отдельный офлайн-экран. Студия/библиотека/UI kit используют network-first HTML с fallback; статические файлы — cache-first. Аудио не скачивается для офлайна автоматически. Баланс mock-режима и черновик сохраняются локально независимо от worker.

**Не кэшируются:** API, POST-запросы, RSC-потоки, административные HTML-страницы, вход, профиль и пополнения. При попытке открыть их без подключения показывается общий офлайн-экран. Новая версия worker ждёт согласия через кнопку «Обновить»; старые кэши NEON SOUND очищаются при активации. Встроенные тесты проверяют manifest, размеры PNG, исключения для API/финансов/админки и offline fallback.

Установку поддерживают не все встроенные браузеры. Нужны HTTPS либо loopback localhost. **127.0.0.1 на телефоне — сам телефон, а не компьютер с сервером.** Для установки с физического телефона потребуется доступный телефону HTTPS-адрес сервера; публичная публикация сейчас не выполнялась. Адаптивный интерфейс работает и как обычный сайт без установки. Учтены нижняя навигация, safe-area и отдельное меню админки с горизонтальной прокруткой широких таблиц.

### Проверки добавления админки и PWA

Всего 19 автотестов: предыдущие 9 плюс 5 для аудита/админских переходов и 5 для PWA. TypeScript и production-сборка проверяются отдельно. Визуальная проверка новых экранов в текущей сессии ограничена: встроенный браузер открыл служебную страницу с data:-адресом и заблокировал доступ инструмента. Физическая установка на iOS/Android пока не проверялась.

Дополнительно доступна проверка production PWA по HTTP с выполнением worker в изолированном JS-контексте:

```sh
node scripts/verify-pwa.mjs http://127.0.0.1:3100
```

Она загружает реальный манифест/иконки/production chunks, проверяет precache, затем имитирует отсутствие сети и проверяет публичную оболочку, offline-скрипт и fallback для админки. Это не заменяет проверку установки на физическом устройстве.
